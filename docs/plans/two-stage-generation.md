# Двухстадийная генерация: состав процесса, затем маршрут

## Зачем

Живые прогоны #40–#42 (24 кейса × режим live) разложили провалы инвариантов по
одному механизму: модель за один выдох должна author-ить всю коллаборацию —
пулы, роли, шлюзы, ~20 элементов и потоки. На этом выдохе она:

- заводит пул на каждую должность (warehouse: 6–9 пулов там, где по тексту 3–4
  участника), и каждый пул становится отдельным процессом со своим стартом и
  финишем — процесс фрагментируется, развилка тонет в осколке (`has_branching`,
  `roles_as_lanes`, `min_steps`, `expected_participants` проваливаются вместе);
- дорожки называет этапами («логистика», «экспедиция»), из-за чего эвристика
  «роль, объявившая сама себя» их не узнаёт и вопрос о ролях до них не доходит;
- на переспросе переписывает план целиком и теряет содержание (профиль
  [1,3,2] → [8,3,2] — 7 новых «потерянных действующих лиц»).

Разделение убирает класс ошибок по конструкции: состав утверждается отдельным
маленьким ответом модели, а вызов маршрута **физически не может** завести пул,
потому что пулы и дорожки приходят ему готовым каркасом.

## Что меняется

`BPMNGenerator.generate`:

1. **Стадия R — состав.** `_extract_roster(text)` → `call_json(_ROSTER_SYSTEM_PROMPT, ...)`,
   ответ маленький:
   `{"organizations": ["Склад"], "systems": ["WMS"], "counterparties": ["Перевозчик"],
     "roles": [{"name": "Кладовщик", "host": "Склад"}]}`.
   `parse_roster(data, text)` превращает его в каркас плана:
   `participants` = организации + системы + контрагенты (+ роли без хозяина,
   `external: false` — тот же rank-0 гейт «роль без организации», что и сейчас),
   `lanes` = роли с хозяином, `actors` = все имена строками (семантика
   `missing_actors` сохраняется).
2. **Стадия F — маршрут.** `_extract_flow(text, skeleton)` — прежний
   `_SYSTEM_PROMPT` без раздела «Пулы и дорожки» (он переехал в R), с
   приложенным каркасом; ответ — только `elements` и `flows`. Каркас
   подставляется и в `_RETRY_TEMPLATE`, чтобы переспрос тоже не заводил пулов.
3. Оба ответа склеиваются в прежний словарь плана → `plan_gaps`, `_reask_improves`,
   `_clarify_ownership`, `repair_structure`, `_generate_bpmn_xml` не меняются.

## Границы честности

- Хозяина роли не угадываем (`_sole_role_host` уже откатывался в #37): роль без
  `host` остаётся нарушением, которое закрыта только модель.
- Лишний пул, который стадия F всё-таки назовёт, принимается только если имя
  звучит в описании; иначе шаг остаётся в каркасном пуле, а заметка честит
  расхождение.
- Сбой стадии R (LLM/разбор) откатывается к прежнему одношаговому пути —
  генерация не имеет права стать отказом из-за новой стадии.
- Цена: +1 вызов модели (~5–8 с), согласовано с владельцем продукта.

## Проверка

- Юнит: `parse_roster` (роли → дорожки, роль без хозяина → rank-0 гейт, хозяйский
  пул из текста), склейка каркаса с ответом F, переспрос держит каркас, откат к
  одношаговому пути при сбое R.
- `python -m pytest tests/ -q`, `python -m eval.run --mode replay`
  (детерминированно, без сети), затем live `--repeat 3` до/после: целевые
  `expected_participants` (0.42–0.54), `roles_as_lanes` (0.75–0.79),
  `has_branching` (0.75–0.79), `min_steps`, плюс `latency_ms` и число вызовов.
