Правка: `core/llm_client.py` — вместо одного имени `GigaChat` пул `GIGACHAT_MODEL`
(по умолчанию `GigaChat-2, GigaChat-3-Lightning`); следующую модель просят, когда
провайдер не знает текущего имени.

Запрос: `POST /api/generate` на живом GigaChat, текст — сценарий `WAREHOUSE_TEXT`
из `eval/scenarios.py`.

- HTTP: 200 (до правки — 503 «No such model»)
- вызовов модели: 2
- балл скоринга: 78
- нарушения плана после починки: 1
- не пройденные правила скоринга: guarded_cycles, task_types, documentation

Ответила `GigaChat-2` — первая в пуле: перехода по пулу в логе backend нет, 404
больше не появляется.

## Осталось непроверенным

Качество самой схемы (балл ниже 100, нарушение про шлюз развилки) — содержание
ответа модели, а не транспорт. Сравнение `GigaChat-2` и `GigaChat-3-*` между собой
меряется прогоном `python -m eval.run --mode live`.

## Нарушение плана (дословно из ответа API)

> описание задаёт условие («Если товара недостаточно, комплектатор собирает частичную отгрузку и ждёт поступления оста…»), а в плане ни одного шлюза, который раздваивает или сливает маршрут: развей маршрут gateway (exclusive — когда дальше идёт одна ветка, parallel — когда несколько одновременно). Шлюз с одним входящим и одним исходящим — не развилка, а обычный шаг. Если развилки в описании на самом деле нет, верни план без изменений
