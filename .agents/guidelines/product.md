# Product Rules

## Когда использовать

Открывай этот файл для продуктовых описаний, документации, терминологии,
определения актуальных разделов и решений о границах продукта.

## Позиционирование

Платформа — внутреннее единое окно ВкусВилл по работе с бизнес-процессами
и единая точка их оптимизации. Она объединяет:

- генерацию BPMN-схем через ИИ по текстовому описанию процесса;
- поиск узких мест и улучшение процессов через ИИ;
- автоматический скоринг качества схем по набору правил;
- реестр бизнес-схем: диаграммы, папки, команды, общий доступ;
- апрувы: предложенные ИИ улучшения применяются к схеме только после
  явного принятия пользователем;
- делегирование и командную работу: роли, приглашения, доменные
  приглашения, передача схем команде.

Не своди продукт к «редактору BPMN» или «чату с LLM». В пользовательских
описаниях используй названия возможностей, а не пути к файлам, классы
и внутренние имена компонентов.

## Терминология

- `Бизнес-процесс` — последовательность действий организации, описанная
  в нотации BPMN 2.0 (XML).
- `BPMN-схема`, `диаграмма` — сохранённый пользователем или командой
  XML-документ процесса с названием, оценкой и историей.
- `Реестр бизнес-схем` — экран «Мои схемы»: личные и командные диаграммы,
  папки, поиск и восстановление удалённых.
- `Генерация` — создание BPMN-схемы ИИ по текстовому описанию
  (`/api/generate`), с последующей авто-раскладкой в редакторе.
- `Скоринг`, `оценка качества` — правило-ориентированный балл схемы
  по 13 взвешенным правилам (события, шлюзы, именование, циклы и т.д.)
  с рекомендациями (`/api/evaluate`).
- `Узкие места`, `улучшение` — анализ схемы ИИ (RAG по корпусу типовых
  процессов + LLM) и предложение улучшенной версии (`/api/ai/improve`).
- `Апрув улучшения` — предложенная ИИ версия сохраняется как ожидающая
  (pending improvement) и попадает в схему только через явное принятие
  (`/api/ai/accept-improvement`).
- `Команда` — рабочее пространство с участниками, ролями и общим
  реестром диаграмм и папок.
- `Роли` — `admin`, `editor`, `viewer`; права хранятся как набор флагов
  (`viewRegistry`, `editRegistry`, `viewRoles`, `manageRoles`).
- `Приглашение` — одноразовый токен по email или по домену почты,
  с ролью и сроком действия.
- `Общий доступ` — разовая ссылка-токен на диаграмму с правом просмотра
  или редактирования и сроком действия.
- `RAG-корпус` — набор эталонных `.bpmn`-файлов в `core/bpmn_dataset/`,
  по которому ИИ ищет похожие процессы при улучшении.
- `LLM-провайдер` — Foundation Models API (OpenAI-совместимый), модель
  `openai/gpt-oss-120b`; резервный контур — Together.ai.

## Актуальные возможности

- регистрация, вход, профиль, восстановление пароля (через email);
- генерация схемы по описанию и авто-раскладка;
- редактор на bpmn-js с панелью свойств, импорт/экспорт `.bpmn`;
- скоринг качества с рекомендациями и оптимизированным XML;
- улучшение схемы через ИИ и апрув предложенных изменений;
- реестр: диаграммы, папки (дерево), перемещение, мягкое удаление
  с восстановлением;
- общий доступ по токену (просмотр/редактирование, срок действия);
- команды: создание, роли, приглашения по email и по домену, состав,
  передача диаграмм команде;
- справочные разделы: гайдлайны моделирования и типовые ошибки;
- экспорт схем (в т.ч. в изображения).

## Данные и хранение

- Диаграммы, папки, пользователи, команды, роли, приглашения, токены
  доступа и ожидающие улучшения хранятся в серверной БД (сейчас SQLite
  `bpmn.db`, целевое состояние — PostgreSQL).
- JWT-токен сессии хранится в `localStorage` браузера и передаётся
  заголовком `Authorization: Bearer`. Это недоверенный ввод для сервера.
- Кэш RAG-индекса — локальные pickle-файлы; это производные артефакты,
  а не источник истины.
- Экспортированные файлы (`.bpmn`, `.svg`, `.png`, `.xml`) лежат в
  `static/` и раздаются сервером.

## Как писать о продукте

- Пиши со стороны пользователя: аналитика, владельца процесса или
  руководителя команды ВкусВилл.
- Для обзоров используй человекочитаемые названия: «реестр схем»,
  «редактор», «генерация по описанию», «апрув улучшения», «командный
  доступ», а не имена файлов и endpoint-ов.
- Не выдавай служебные механизмы (кэш, миграции, логирование) за
  самостоятельные продуктовые разделы.
